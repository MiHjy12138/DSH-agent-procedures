# 经验流程（procedures）

各工作区 `procedures/` 存**踩过的坑与解法**，不常驻注入，按需读。

- **动手前**：任务撞上「网页抓不到正文 / 插件改了不生效」这类现象，先**搜**触发词，别凭记忆答：
  拿任务里的现象词搜 `procedures/*.md`（POSIX：`grep -rl "<现象词>" procedures/`；Windows PowerShell：`Select-String -Path procedures\*.md -Pattern "<现象词>"`），
  命中哪张 read 哪张。拿不准就多搜一个词 —— 几十字节，远好过重走一遍试错。卡少或搜不动时，列目录看文件名挑卡，一样算数。

- **踩到坑的当时 —— 最重要的一条**：只要这次不是「照着卡做就顺了」，而是**又试错了几轮**，就立刻往 `procedures/_inbox.md` 记一行（现象 + 一句话解法）。
  **别等收尾** —— 收尾要靠回忆，回忆不可靠；当下记，不会忘。**记一行也算数，别因为没想清楚就不写。**
  **记 inbox 是记笔记、不是"动手改文件"** —— 就算被要求「只读 / 先别动手」，也照记不误；
  **但任务若明令「只读」**（例如"不要创建任何文件"），就把那一行写在**回复末尾**并注明「待记 inbox」，由上层或下次会话补写 —— 既不违令，也不丢痕。

- **收尾时（是检查，不是回忆）**：在说出「完成 / 搞定了 / 修好了」之前，看一眼 `_inbox.md`：
  - 有够格的（复发的 / 代价大的）→ 照 `_模板.md` 整理成正式卡，删掉那行 inbox。**文件名就是索引**：写成 `分类-现象`，现象词用「任务里会出现的说法」。
  - 只是小意外 → 留在 inbox，下次开工再整理。

- **一张卡写四条**：触发条件 / 首选姿势（可直接抄）/ 反面清单（试过不通的）/ 验证方式（怎么确认真成了）。

- **不扫描、不复制**：不做启动式全库扫描；检索一律**定向** —— 拿任务里的现象词去搜，命中几张读几张。卡片正文不进本文件，本文件与 INDEX 只放指针。
