# 原 procedures 的可优化点

基于原仓库 `701b501`。原仓库已经有很好的骨架：文件名索引、消歧层、audit/review、按需读卡。
下面是我建议的优化方向，原则是**别再加一套记忆/索引**。

## P0：先守住成本和质量

1. **Token 预算写进测试**
   - 全局钩子建议 ≤ 1.5 KB；
   - `INDEX.md` 建议 ≤ 1 KB，并验证它不随卡数增长；
   - 单卡建议 ≤ 3 KB；
   - 加一个测试/CI 检查这些数，防止慢慢膨胀。

2. **audit 进 CI**
   - 已有 `tools/procedures-audit.mjs`，把它接到 pre-commit/CI；
   - 检查必填段、触发行、链接、体积、过期线索；
   - 卡库变更时跑一遍，而不是靠人记得。

3. **review 保持可选**
   - `procedures-review.mjs` 依赖 DSH 会话日志，是 DSH-only；
   - 不要把它说成跨 harness；放到可选附件，不阻塞主线；
   - 没有会话日志时，用 `_layers.md` 的时间阈值做降级。

4. **不要新增逐卡索引/catalog**
   - 原 README 的“文件名就是索引”已经是对的；
   - 需要搜索时，用文件名/触发行/正文定向搜；
   - 本地工作台可以用临时索引，但不提交、不注入、不常驻。

## P1：本地经验库工作台

- 单独做 CLI + 本地网页，复用 `procedures` 卡格式和 `procedures-audit`；
- 不自动捕获、不自动写记忆、不加全局钩子；
- 这是和 Memorax 错开的关键：Memorax 管记忆，工作台管 repo 文档。

## P2：小范围健壮性

- **全局钩子安装器**：默认 dry-run，`--apply` 才写，备份放目标旁，支持 `DSH_HOME` 等环境变量；
- **POSIX/只读**：`grep -rl` 示例和只读 inbox 兜底；
- **跨平台**：路径/CRLF 归一，Windows 和 POSIX 都测；
- **不自动建项目**：用显式脚本，不做文件系统监听。

## 不建议做

- 项目库/中心库再分层：原仓库单库 + 文件名索引已经够；跨项目交给 Memorax；
- 自建 catalog/finder 作为常驻索引；
- 全局 hook 自动跑安装/自动补库；
- 把卡逐张 `memorax-cli add`（只增不改/不删，会留旧版本）；
- 双向同步 Memorax；
- 把项目专属数据写进任何共享记忆。

## 推荐顺序

1. 成本/质量 CI（P0）；
2. 本地经验库工作台（P1）；
3. 安装器/POSIX/只读的小补丁（P2）。

这样原 procedures 保持“小而稳”，新工作台只负责本地查看/编辑/审计，不会和 Memorax 抢记忆。
