# 项目经验库工作台（设计）

## 定位

一个**项目本地、跟着 repo 走、可 review** 的经验卡工作台。

- 只读/写当前项目的 `procedures/`；
- 不做自动捕获、不做自动 writeback、不做全局钩子；
- 只服务当前项目，不跨项目；
- 项目专属 ID、哈希表、数据表、绝对路径只留本项目。

## 数据格式

沿用原仓库 `procedures/*.md`：

- 文件名 = `分类-现象`，文件名本身就是索引；
- `> **触发**：` 写任务里会出现的现象词；
- `> **验证**：` 写怎么确认这次真的成了；
- 卡内四段：首选 / 被挡时 / 别再来 / 注意；
- `_layers.md` 可选：`fixed` / `env` / `task`；
- `INDEX.md` 只做消歧，不逐卡列；
- 不新增逐卡 catalog。

## 搜索逻辑

借鉴成熟记忆工具的检索纪律，但**不接任何记忆服务**：

1. **只在有历史依赖时搜**：任务依赖先前经验、旧修复、历史决策、已知死路时才搜；简单当前事实不搜。
2. **查询写意图**：`目标: 条件，决策/验证?`，不要只丢一串名词。
3. **handle 优先**：错误码、路径、命令、配置键、文件名比泛词权重高。
4. **作用域锁在当前工作区**：只搜当前项目的 `procedures/`。
5. **top-k 路由**：默认 5 条，先给路径/标题/摘要；按需打开 1–2 张。
6. **接受门槛**：IDF 稀有词 + 停用词过滤；quoted 短语/handle 必须命中；不把“为什么/怎么/问题”这类泛词当证据。
7. **渐进披露**：列表 → 卡片 → 段落，不整库读、不整库注入。

实现：

- `workbench/lib.mjs`：扫描 + IDF 打分 + CJK 2/3-gram + 停用词；
- `workbench/cli.mjs search`：路径/摘要输出；
- 网页搜索复用同一套逻辑。

## 索引逻辑

- **文件是唯一 source of truth**；
- 索引在启动/调用时派生，不提交、不常驻、不注入；
- 按工作区隔离；不跨项目合并；
- 不生成逐卡 catalog；
- 卡片多了再换本地 FTS/trigram，接口不变；
- 搜索索引只用于本地 UI/CLI，不进入模型上下文。

## 钩子逻辑

- 可选，**项目级**，短的一句；
- 只在任务需要时提醒“有经验库、按需搜”；
- 不自动搜索、不自动注入卡片、不自动捕获、不自动写记忆；
- 不常驻后台、不做文件监听；
- 模板：`workbench/AGENTS-snippet.md`。

## 体验（MVP）

- 三栏：搜索/筛选列表、Markdown 预览、审计抽屉；
- 新建卡片：触发现象 + 首选 + 死路 + 验证；
- 编辑：原文 Markdown，保存到 `procedures/`；
- 审计：复用 `tools/procedures-audit.mjs`，显示 P0/P1；
- 收件箱：先记一行，稍后整理；
- 快捷键：`/` 搜索、`N` 新建、`E` 编辑、`Ctrl/⌘+S` 保存、`Esc` 取消/关闭；
- 本地网页，无外部依赖、无网络、无后台服务。

## 技术栈

- Node.js 24 + 原生 HTTP + 浏览器 UI；
- 不先上 Electron/Tauri；
- 复用原仓库审计工具；
- 可选：以后加 MCP `search/read/write`，但默认不启动。

## 实施顺序

1. `lib.mjs` 搜索/审计核心；
2. `cli.mjs search/show/audit/inbox`；
3. 本地网页；
4. 测试夹具；
5. 可选 MCP。

## 成功标准

- 不增加全局 token；
- 不自动捕获、不跨项目、不写共享位置；
- 本地搜索能在 3–5 条内路由到卡；
- 卡片能跟 repo 走、能 review、能回滚。
